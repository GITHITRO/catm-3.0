# Catman 3.0 — AI-First Blueprint (SSOT v1.1)

> **Статус:** рабочий документ — навигатор решений
> **Дата фиксации:** 2026-09-17
> **Назначение:** единый артефакт для человека и ИИ-агента. Из разделов 1, 3, 5, 12 режется будущий `AGENTS.md` демо-агента.
> **Владелец:** Ro Ro

## 0. Как читать

- **Человеку:** разделы 1–14 по порядку.
- **ИИ-агенту:** обязательны разделы 1 (цель), 3 (архитектура), 5 (скиллы), 12 (инварианты); остальное — контекст.
- Документ эволюционирует: удачный диалог агента складывается обратно в скиллы, а не теряется.

## 1. Целеполагание

### 1.1 ИКР — идеальный конечный результат

Catman открывает рабочее место → в первые секунды видит 3–5 приоритизированных карточек проблем с суммой в деньгах → клик → причина, график, 2–3 сценария с эффектом на маржу → **человек выбирает** → детерминированный скрипт исполняет → лог решения сохранён.

Каждое число проверяемо. Каждое решение — за человеком.

### 1.2 Цели

- **G1.** Доказать контур «агент нативно встроен в данные Catman» на одной категории за 2 недели.
- **G2.** Вау-эффект от глубины и grounded-инсайтов, а не от полировки UI.
- **G3.** Продать двойную роль: ИИ-специалист (архитектура) + ИИ-проектный менеджер (доставка с метриками).
- **G4.** Демо-стенд по ссылке, устойчивый к сбою (обязательное запасное видео).

### 1.3 Анти-цели (что НЕ делаем)

- Не строим мультиагентный рой с первого дня.
- Не кладём промо-плейбук целиком в конституцию.
- Не рисуем графики токенами модели.
- Не даём агенту писать в ERP/CRM без approve.
- Не тащим GitHub-скиллы без аудита.
- Не делаем «театр эвристических комнат».

## 2. Диагноз (почему Frontend-first отвергнут)

Эвристический Frontend-first хрупок:

- по робастности: широкие полномочия Catman ломают заранее прошитые сценарии;
- по аудитории: C-level читает это как «очередной BI», «пыль в глаза»;
- по времени: жрёт часы на «как сделать» и полировку.

**Решение:** фронт инвертируется. Комнаты становятся маршрутами скиллов, а не срежиссированным нарративом. Вау даёт артефакт скилла: короткий инсайт + график из кода + карточка решения с оценкой эффекта.

## 3. Целевая архитектура (БАЗА — подтверждена)

| Слой | Что живёт | Чего не делать |
|---|---|---|
| Данные | Контракты Catman 3.0, грид, метрики, lineage | Кормить LLM сырым Excel без схемы |
| Конституция | `AGENTS.md` < 150 строк: роль, комнаты, антигаллюцинации, голос C-level | Пихать промо-плейбук целиком |
| Скиллы | Платформенные + вертикальные из SSOT | Тащить GitHub-скилл без аудита |
| Тулы | SQL/semantic, chart, decision-card, writeback | Рисовать график токенами модели |
| Поверхность | Чат + живая таблица + артефакты | Театр эвристических комнат |
| Позже | LangGraph на промо/ассортимент; KAG на онтологию | Граф как UX с дня 1 |

**Ключевое правило:** число без tool-call в семантический слой = баг продукта, а не «креатив».

Не мультиагентный рой и не harness как runtime ARM, а паттерн «конституция + скиллы по требованию + тулы/MCP».

## 4. Agent-Driven UI

### 4.1 Morning Brief

- Ночью скиллы сканируют SSOT (batch-job с eval, не «агент подумал»).
- Утром 3–5 Problem Cards, ранжированных по Δ P&L из SSOT, не из тона LLM.
- Клик / Space → BriefWidget: root cause, график, 2–3 сценария с эффектом.

### 4.2 Комнаты = контекстные хабы

Вход в «Комнату Промо» поднимает skill pack и фильтрует общий поток карточек. Визуальный холст остаётся тем же. Агент — оператор состояния, не декоратор дашборда.

### 4.3 Каталог GenUI (жёсткий, не свободный)

- `ProblemCard` — проблема, Δ денег, уверенность, источник
- `BriefWidget` — root cause, график, сценарии
- `CampaignCard` / календарь / сравнительная таблица
- `ApprovalGate` — исполнить / отклонить / отложить

Агент выбирает компонент и заполняет слоты данными тулов. Не изобретает кнопки, не верстает layout. Controlled/Declarative GenUI (AG-UI, A2UI), не Open-Ended HTML.

Чат — оператор на длинный хвост, не сцена. Плюс: устранение длинных промптов и громоздких дашбордов — фокус на принятии решений по готовым карточкам.

## 5. Карта скиллов

`AGENTS.md` — оглавление рабочего места: кто агент, какие комнаты, какие скиллы, правило «нет числа без источника», что нельзя без approve. Скиллы — в `.agents/skills/` (конвенция кросс-агентной портативности).

**Платформенные:**

- `table-qa` — вопросы только через схему грида
- `data-visualizer` — код графика (Vega/ECharts) + эталонные скрины в `assets/`
- `decision-card` — варианты, эффект, уверенность, next action
- `cite-ssot` — обязательная привязка к контракту/метрике

**Вертикальные (из SSOT Catman 3.0):**

- `category-brief` — очередь решений, gap, сравнение альтернатив
- `margin-forensics` — mix / price / promo / shrink
- `promo-coach` — лифт, каннибализация, механика
- `assortment-gap` — listing, дубли, whitespace
- позже: `reset-advisor`, `jbp-brief`

Граф живёт **внутри** скилла (detect → diagnose → simulate → recommend → log), не вместо него. LangGraph — рантайм оркестрации с checkpoint и approve для шагов длиннее одного хода. KAG/OpenSPG — когда SSOT перестанет помещаться в references скилла (онтология SKU–promo–store–margin).

## 6. Контур HITL

1. **Детекция:** агент видит отклонение → формирует карточку.
2. **Визуализация:** клик → динамический виджет с графиками и причинами (тот же context_id).
3. **Решение:** человек выбирает сценарий кнопкой.
4. **Исполнение:** агент запускает детерминированный скрипт (ERP/CRM/уведомления) за `ApprovalGate`.

Карточка без источника не рендерится. В карточках и чате — профессиональный, понятный язык без «заумности».

## 7. Роадмапи

### 7.1 Внедрение фич (что видит Catman и C-level)

1. **Недели 0–2.** `AGENTS.md` + `table-qa` + `cite-ssot` на одном гриде одной категории. Первый ответ всегда из данных.
2. **Недели 3–5.** `data-visualizer` + `decision-card`. Вау = инсайт + график + 2 опции.
3. **Недели 6–8.** `promo-coach` + `margin-forensics`. Eval-набор: 20 золотых вопросов Catman 2.0, галлюцинация = fail.
4. **Квартал 2.** `assortment-gap` + `category-brief`. Комнаты — скилл-маршруты, фронт — canvas артефактов. Morning Brief (ночной batch).
5. **Квартал 3.** LangGraph на симуляции промо/ассортимента, writeback с approve.

### 7.2 Эволюция ядра (система стареет вместе с Catman и LLM)

- **Изменяемое ядро** — скиллы и контракты данных, не React-эвристики. Удачный диалог складывается обратно в `SKILL.md`.
- **Модель сменная:** конституция и скиллы живут дольше конкретной LLM.
- **Harness-совместимость:** скилл = плагин; при стабилизации harness-систем Catman подключается как vertical plugin pack, не переписывается.
- **Память практики:** KAG-слой на онтологии Catman, когда SSOT перерастёт references.
- **Саморасширение:** агент предлагает новый скилл, человек аппрувит — это и есть «изменение ядра по лучшим практикам».

## 8. Демо-стратегия

### 8.1 Пирамида

| Уровень | Формат | Что даёт | Когда |
|---|---|---|---|
| 1. Повествование | Видео 90–180 сек | Управляемая история без риска фейла | Первая встреча, рассылка |
| 2. Суть | Слайды, 6 шт | Экономика, риски, роадмап | Встреча с C-level |
| 3. Доказательство | Живое демо 5–10 мин | «Это работает на самом деле» | Когда спросили |
| 4. Вовлечение | Песочница | Человек сам печатает | После решения о пилоте |

Каждый уровень сам продаёт следующий. Видео заканчивается приглашением «покажу вживую за 5 минут».

**Слайды (6):** боль (до 80% недели в таблицах) → цена вопроса → до/после (таблица vs карточка) → как работает (одна картинка, 5 блоков) → границы (что решает ИИ, что человек, где аудит) → роадмап пилота (3 шага, одна категория, одна метрика в деньгах).

**Живое демо:** подготовленный вопрос, знакомая категория, запасной сценарий, стенд проверен за час до встречи, запасное видео как план Б.

### 8.2 Двухвидеовая стратегия

**Видео №1 (основное, для всех):** сценарий Catman на Claude. Claude-first — осознанный выбор: якорь надёжности для C-level (знакомая экосистема), максимальный интеллект агента сегодня, свежайший SOTA-паттерн (16.09.2026 Anthropic влил Cowork в основной чат: скиллы + коннекторы + саб-агенты в одном интерфейсе). Видео строится вокруг боли Catman, не вокруг вендора. Финальный слайд — переносимость (атом правды №1).

**Видео №2 (для тех, кто спросил):** «Тот же результат на открытом стеке» — тот же набор скиллов, те же инструменты, запуск в OpenWork с открытыми моделями по API, упоминание self-host. Это не оправдание, а вторая демонстрация навыка: «соберу под любой бюджет и ограничения по данным».

**Критерий запуска видео №2:** минимум один зритель видео №1 задал вопрос про доступ, стоимость, локализацию данных или несанкционные ограничения — это сигнал спроса, а не гипотетика.

Разделение психологически важно: видео №1 продаёт бизнес-результат, видео №2 продаёт глубину инженерии — разным аудиториям. Не смешивать.

### 8.3 Атомы правды для видео (дословные формулировки)

**Атом 1 — финальный слайд видео №1 (20–30 сек):** «Стек выбран сознательно: Claude даёт максимальное качество агента сегодня. Но архитектура не привязана к вендору: скиллы и инструменты — в открытом стандарте SKILL.md, который понимают Codex, Gemini, OpenCode и OpenWork. GLM-модели имеют открытые веса под MIT — при желании всё разворачивается локально, вплоть до своего GPU-сервера. Мы выбрали лучший инструмент под задачу и оставили себе свободу замены».

**Атом 2 — ответ на «почему сразу не выбрал открытые?»:** «Выбор инструмента — часть компетенции, а не лояльность бренду. Сначала доказываем результат на сильнейшем стеке, затем показываем переносимость на открытых системах для тех, кому это критично. Скиллы — мой переносимый актив, не ставка на вендора».

**Атом 3 — честная граница качества (не обещать лишнего):** «Открытые модели дают сопоставимое качество для большинства задач категории; полный паритет топовых моделей требует мульти-GPU нод (GLM-5.2 FP8 ≈ 8× H200, INT4 ≈ 4× H200)».

**Атом 4 — главная рамка всех видео:** «Я собираю агентов под боли бизнеса. Стек — open-source, модель сменная, финальное решение всегда за человеком».

**Атом 5 — слайд «Где это работает» (таблица режимов):**

| Режим | Требования | Качество |
|---|---|---|
| API (Z.AI GLM) | Ключ API | Как в демо, копейки за токены |
| OpenWork локально | Рабочая машина | Те же скиллы, модель по API или компактная локально |
| On-prem GPU-нода | 4–8× H200 | Та же модель буквально (открытые веса MIT) |

**Атом 6 — критерий видео №2:** см. 8.2.

## 9. Позиционирование

- **Видео** = от проектного менеджера с глубокой отраслевой экспертизой: и для проекта, и для «сеньор»-роли катмена, с последующей интеграцией инструментов «в жизнь» компании.
- **Голос** (особенно поставленный) — лучшая презентация: уверенная речь, описание, убеждение. Свой голос довереннее ИИ-голоса; гибрид — клон своего голоса (правки текстом без перезаписи).
- **Слайды** — «вишенка», в т.ч. из разряда «как устроено и почему не галлюцинирует и работает без ошибок».
- **Двойная роль одной цепочкой владения:** не два списка навыков, а «я спроектировал (артефакты: AGENTS.md, скиллы, стенд) и я доставляю (до/после, роадмап, метрики, границы, HITL)».
- **Рамка для C-level:** «95% корпоративных ИИ-пилотов без ROI — из-за отсутствия системы измерения и управления, а не слабой модели. Мой контур построен вокруг метрик и человеческого решения».

## 10. Экосистема и развёртывание

### 10.1 Выбор для демо: Claude-first

- Якорь надёжности: знакомая C-level экосистема снижает воспринимаемый риск; внимание зрителя — на боль Catman, не на оправдание стека.
- Максимальный интеллект сейчас: меньше дублей и дрейфа при записи, плотнее инсайты на живом демо.
- Тайминг: с 16.09.2026 Cowork слит с чатом Claude — скиллы, коннекторы, саб-агенты, документы и слайды в одном интерфейсе; это ровно наш проектируемый паттерн.
- Claude в кадре — только двигатель. Видео №1 — про Catman, не про вендора.

### 10.2 Режимы развёртывания

Таблица режимов — атом 5 из раздела 8.3. Формулировка для вопросов «как мы будем работать»: «те же скиллы и тот же контур — где угодно; модель выбирается под бюджет и требования к данным».

### 10.3 Переносимость

`SKILL.md` — межвендорный стандарт (Codex, Claude Code, Gemini CLI, OpenCode, OpenWork, Cursor и др.): скиллы Catman — переносимый актив, не ставка на вендора. Выбор экосистемы перестал быть необратимым.

### 10.4 Стенд и RF-фильтр

- **Стенд (тест):** Railway template OpenCode (persistent volume `/data`, `OPENCODE_SERVER_PASSWORD`, trial credit) — быстрый прогон, НЕ гарантия 24/7.
- **Oracle Always Free:** исключён по результату проверки (не работает в нашем случае).
- **HermesOS Free Tier:** не подтверждён надёжными источниками — не использовать без ручной проверки.
- **Резерв:** свой лёгкий runtime (GitHub Pages + Cloudflare Worker + внешний LLM API) или дешёвый VPS ($4–10/мес).
- **Модель:** Z.AI GLM Flash (free, РФ-доступен) с fallback на другие OpenAI-совместимые API. Free tokens — ресурс вычисления, не SLA.
- **RF-фильтр:** cloud-экосистемы (Google/OpenAI/Anthropic) — не основа публичного стенда для пользователей из РФ; только личный инструмент записи.
- **Правило доступа:** люди получают только WebUI URL, не shell. Двухзонность `/agent` (пользователи) и `/admin` (настройка скиллов, ключей, approve-политик).

## 11. Производство видео

- **Конвейер A (ИИ озвучка):** ElevenLabs (русский поддерживается) / Synthesia (запись продукта в браузере → редактируемое демо). Быстро, но голос «слишком идеальный» для C-level.
- **Конвейер B (свой голос + ИИ-монтаж):** Descript — запись экрана → транскрипция → монтаж правкой текста, вырезание пауз, автотитры.
- **Гибрид (рекомендуется):** клон своего голоса один раз → дальше наррация перегенерируется правкой сценария.
- **Разделение труда:** запись экрана — человек (только реальный стенд, никаких stock-кадров — C-level видит «сделку»); монтаж, титры, паузы, транскрипция — ИИ.
- **Предел:** полностью агент-собранные видео (Fotor Agent, InVideo) — для маркетинговых клипов, не для демо продукта. Финальный контроль темпа и акцентов — за человеком. Аргумент рамки «ИИ ускоряет, человек решает».

## 12. Критические якоря (инварианты — не нарушать)

1. Число без источника (tool-call в SSOT) = баг продукта, не «креатив».
2. График — только из инструмента (код → Vega/ECharts → PNG/HTML), не токенами модели.
3. Агент не пишет в ERP/CRM/промо-план сам — только предложение + `ApprovalGate`.
4. Конституция < 150 строк; скиллы подгружаются по требованию (progressive disclosure).
5. Общие скиллы с GitHub — только после аудита (могут увести агента во внешнюю сеть).
6. Комната = skill pack + фильтрация потока карточек, не статичный дашборд.
7. GenUI = каталог доверенных компонентов, не свободный layout.
8. Финальное решение — всегда за человеком.
9. После живого прогона правим скиллы и тулы, не интерфейс.
10. Демо без запасного видео не проводится.
11. Язык для C-level и Catman — профессиональный и понятный, без заумности и модных слов.
12. Карточка без источника не рендерится.
13. Видео №1 строится вокруг боли Catman, не вокруг вендора; стэк-оправдания — только финальный слайд переносимости.
14. Не обещать «то же качество локально» без оговорки о GPU-нодах (атом 3).
15. Видео №2 — только по сигналу спроса (атом 6), не впрок.

## 13. SOTA-подтверждения (сводка)

- **Agent Skills / progressive disclosure:** Anthropic; agentskills.io — `SKILL.md` как открытый стандарт; поддержан Codex, Gemini CLI, OpenCode, OpenWork и др.
- **Claude Cowork → единый чат (16.09.2026):** скиллы, коннекторы, саб-агенты, документы и слайды в одном интерфейсе — актуальный SOTA-паттерн агентного рабочего места.
- **Открытые веса:** GLM (Z.ai) — MIT-лицензия, self-host возможен; полный паритет топовых моделей требует мульти-GPU нод (8× H200 FP8 для GLM-5.2).
- **OpenWork:** open-source (MIT) альтернатива Cowork/Codex, local-first, скиллы + MCP, любой API-ключ.
- **AGENTS.md** — always-on контекст проекта-индекс; стандарт 2026.
- **Оркестрация длинных решений:** LangGraph — checkpoint, approve, retail-кейсы.
- **Заземление фактов:** KAG/OpenSPG (Ant Group) — для профессиональных доменов, где vector-RAG шумный.
- **Вертикальные ориентиры:** SymphonyAI CINDE Merchandising Agents; SAP Joule CM Assistant — закупной, в retail-питч не мешать.
- **GenUI-протоколы:** AG-UI, A2UI — controlled/declarative, стрим состояния, interrupt на approve.
- **Demo-практики:** пирамида видео/интерактив/песочница; exec-демо = минимум слайдов, боль, цена бездействия, ROI-метрика.
- **Софт:** Descript (монтаж текстом), ElevenLabs v3 (RU), Synthesia (демо из записи браузера).
- **Экономика Catman:** category teams тратят 25–80% недели на сборку данных — обоснование проектирования агента вокруг грида.
