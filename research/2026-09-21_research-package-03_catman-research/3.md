```markdown
# Роль и правила
Вы — детерминированный аналитический ассистент. Вычисления производятся строго через SQL/Python.
Галлюцинации и аппроксимация цифр запрещены.

# Формулы Price-Volume-Mix (PVM)
При анализе изменения валовой маржи между текущим периодом (T) и базовым/плановым (B):
1. Эффект цены (Price Effect): sum((Price_T - Price_B) * Quantity_T)
2. Эффект объема (Volume Effect): (Total_Qty_T - Total_Qty_B) * sum(Share_B * Margin_B)
3. Эффект структуры (Mix Effect): Total_Qty_T * sum((Share_T - Share_B) * (Margin_B - Avg_Margin_B))
4. Эффект себестоимости (Cost Effect): sum((Cost_B - Cost_T) * Quantity_T)

# Процесс
1. Сформируйте безопасный SQL-запрос к витрине `v_category_pvm_summary`.
2. Сопоставьте падение продаж с фактами Out-of-Stock (`closing_stock == 0`).
3. Сформируйте Evidence Pack с таблицей декомпозиции.

```

#### 2. Реализация Safe-SQL MCP сервера на Python (`fastmcp` + `sqlglot`)

```python
import sqlite3
import time
from typing import Any, Dict
from mcp.server.fastmcp import FastMCP
import sqlglot
from sqlglot import exp

mcp = FastMCP("Catman-SafeSQL")
DB_PATH = "catman_retail.db"
ALLOWED_TABLES = {"dim_product", "fct_sales_daily", "fct_inventory_daily", "fct_plan_monthly", "v_category_pvm_summary"}

def sanitize_sql(query: str) -> str:
    parsed = sqlglot.parse(query, read="sqlite")
    if not parsed or len(parsed) > 1:
        raise ValueError("Разрешен только один SQL-запрос.")
    stmt = parsed[0]
    if not isinstance(stmt, exp.Select):
        raise PermissionError("Разрешены только операции SELECT.")
    tables = {t.name.lower() for t in stmt.find_all(exp.Table)}
    if tables - ALLOWED_TABLES:
        raise PermissionError(f"Запрещенные таблицы: {tables - ALLOWED_TABLES}")
    if stmt.args.get("limit") is None:
        stmt = stmt.limit(1000)
    return stmt.sql(dialect="sqlite")

@mcp.tool()
def execute_safe_query(sql: str) -> Dict[str, Any]:
    try:
        clean_sql = sanitize_sql(sql)
        conn = sqlite3.connect(f"file:{DB_PATH}?mode=ro", uri=True)
        conn.execute("PRAGMA query_only = ON;")
        cur = conn.cursor()
        cur.execute(clean_sql)
        rows = cur.fetchall()
        cols = [c[0] for c in cur.description] if cur.description else []
        conn.close()
        return {"status": "success", "executed_sql": clean_sql, "data": [dict(zip(cols, r)) for r in rows]}
    except Exception as e:
        return {"status": "error", "message": str(e)}

if __name__ == "__main__":
    mcp.run()

```

```python
import sqlite3, datetime, random

conn = sqlite3.connect("catman_retail.db")
cur = conn.cursor()
cur.execute("CREATE TABLE IF NOT EXISTS dim_product (sku_id TEXT PRIMARY KEY, sku_name TEXT, category TEXT, base_cost REAL, base_price REAL);")
cur.execute("CREATE TABLE IF NOT EXISTS fct_sales_daily (date TEXT, sku_id TEXT, units INTEGER, gross_sales REAL, cogs REAL, margin REAL, is_promo INTEGER, PRIMARY KEY (date, sku_id));")
cur.execute("CREATE TABLE IF NOT EXISTS fct_inventory_daily (date TEXT, sku_id TEXT, stock INTEGER, is_oos INTEGER, PRIMARY KEY (date, sku_id));")
cur.execute("CREATE TABLE IF NOT EXISTS fct_plan_monthly (month TEXT, category TEXT, target_sales REAL, target_margin REAL, PRIMARY KEY (month, category));")

products = [
    ("SKU-101", "Молоко 3.2% 1л", "Dairy", 45.0, 75.0),
    ("SKU-102", "Масло Сливочное 82.5% 180г", "Dairy", 110.0, 180.0),
    ("SKU-103", "Творог 9% 200г", "Dairy", 60.0, 105.0)
]
cur.executemany("INSERT OR REPLACE INTO dim_product VALUES (?,?,?,?,?)", products)

start = datetime.date(2026, 8, 1)
for d in range(30):
    dt = (start + datetime.timedelta(days=d)).isoformat()
    for sku, name, cat, cost, price in products:
        is_promo = 1 if (10 <= d <= 16 and sku == "SKU-102") else 0
        p = price * 0.85 if is_promo else price
        if d in (14, 15, 16) and sku == "SKU-102":
            stock, is_oos, units = 0, 1, 0
        else:
            stock, is_oos = random.randint(20, 100), 0
            units = random.randint(80, 140) if is_promo else random.randint(20, 50)
        cur.execute("INSERT OR REPLACE INTO fct_sales_daily VALUES (?,?,?,?,?,?,?)", (dt, sku, units, p * units, cost * units, (p - cost) * units, is_promo))
        cur.execute("INSERT OR REPLACE INTO fct_inventory_daily VALUES (?,?,?,?)", (dt, sku, stock, is_oos))

cur.execute("INSERT OR REPLACE INTO fct_plan_monthly VALUES ('2026-08', 'Dairy', 500000.0, 180000.0);")
cur.execute("""CREATE VIEW IF NOT EXISTS v_category_pvm_summary AS 
    SELECT s.date, p.category, p.sku_id, p.sku_name, s.units, s.gross_sales, s.cogs, s.margin, s.is_promo, i.is_oos 
    FROM fct_sales_daily s JOIN dim_product p ON s.sku_id=p.sku_id LEFT JOIN fct_inventory_daily i ON s.date=i.date AND s.sku_id=i.sku_id;""")
conn.commit()
conn.close()
```

### 10 наиболее ценных найденных наработок:

1. **[OpenAI DevHub Overview Pattern](https://cdn.openai.com/devhub/videos-learn/chatgpt-work-overview-1080p-v1.mp4)** — эталонный Split-Screen UX (диалог слева, живой артефакт справа, статусы тулов и кнопки Human Approval).
2. **[Anthropic Agent Skills Spec](https://github.com/anthropics/skills?utm_source=gemini)** — промышленный открытый стандарт структурирования предметной логики в `SKILL.md`.
3. **[Model Context Protocol SQLite](https://github.com/modelcontextprotocol/servers/tree/main/src/sqlite?utm_source=gemini)** — стандарт детерминированного подключения локальных БД к агентам.
4. **[SQLGlot](https://github.com/tobymao/sqlglot?utm_source=gemini)** — готовый AST-парсер для аппаратно-надежного Safe-SQL контура (блокировка мутаций, whitelisting таблиц, лимиты).
5. **[LibreChat](https://github.com/danny-avila/LibreChat?utm_source=gemini)** — готовый веб-интерфейс с нативным MCP-рантаймом для многопользовательской работы.
6. **[OpenWork](https://github.com/different-ai/openwork?utm_source=gemini)** — готовый открытый локальный десктоп-рантайм (альтернатива Claude Cowork).
7. **[Wren AI Modeling Definition Language (MDL)](https://github.com/Canner/WrenAI?utm_source=gemini)** — семантический слой, предотвращающий ошибки в расчете метрик ритейла.
8. **[Vanna.ai](https://github.com/vanna-ai/vanna?utm_source=gemini)** — RAG-механизм извлечения контекста DDL и каталога проверенных SQL-запросов.
9. **[Tableau Pulse UI Concept](http://www.youtube.com/watch?v=Cnbdkye0X_8&utm_source=gemini)** — эталон визуализации карточки утреннего брифинга с факторами отклонения.
10. **[Python-pptx](https://python-pptx.readthedocs.io/?utm_source=gemini) & [OpenPyXL**](https://openpyxl.readthedocs.io/?utm_source=gemini) — детерминированный пайплайн генерации Excel-моделей и слайдов презентаций.

### Главный вывод: что Catman может взять уже готовым:

* **Интерфейс и рантайм**: LibreChat (Web) или OpenWork (Desktop) полностью закрывают задачу рабочего пространства с нативным MCP.
* **Шина инструментов**: Официальные MCP-серверы `@modelcontextprotocol/server-sqlite` и `@modelcontextprotocol/server-filesystem`.
* **Защитный контур**: SQLGlot для AST-валидации запросов.
* **Генерация артефактов**: Стандартные библиотеки `python-pptx` и `openpyxl`.

### Что не нужно строить с нуля:

* Собственный веб-чат с нуля.
* Собственный протокол подключения к базам данных (MCP стал универсальным стандартом).
* Тяжелые мультиагентные графы (LangGraph/CrewAI) — вся логика реализуется через `SKILL.md` и детерминированные инструменты.

### Уникальная часть Catman (IP проекта):

1. **Категорийная семантическая модель ритейла** (строгие правила джойнов чеков, остатков, промо-планов и исключение галлюцинаций в марже).
2. **Детерминированный скилл Price-Volume-Mix (PVM)** с математической факторизацией отклонений.
3. **Evidence Pack Generator**: связывание каждого вывода с хэшем SQL-выборки, формулой и визуализацией.
4. **Стандарт Decision Memo**: шаблон управленческого решения с расчетом альтернатив и механизмом Human Approval.

### Сцена 3: Запуск Hypothesis Analysis (02:00 – 03:15)

## 6. 5 поисковых пробелов и требуемые данные

1. **Реальная структура таблиц ERP/WMS конкретной торговой сети**: Необходим DDL-дамп боевых таблиц (или выгрузка из SAP/1C/Axapta), чтобы заменить синтетический датасет реальными названиями колонок учета себестоимости, ретро-бонусов и партионного учета.
2. **Ограничения безопасности корпоративного сетевого контура**: Требуется уточнить, разрешен ли исходящий трафик к внешним LLM API (Anthropic/OpenAI) или проект обязан работать строго On-Premise (через локальные веса на сервере с GPU).
3. **Регламент согласования промо-акций (SLA и роли)**: Необходима матрица полномочий: до какого лимита бюджета категорийный менеджер может утверждать действия самостоятельно, и в каких случаях требуется эскалация на коммерческого директора.
4. **Специфика учета промо-компенсаций поставщиков**: Включается ли в расчет чистой маржи (Net Margin) маркетинговый бюджет поставщика на промо (Scan-Back, фиксированные выплаты за ввод в планограмму), чтобы формулы PVM учитывали компенсации.
5. **Целевой канал доставки утреннего брифинга**: Предпочитает ли менеджер получать первичный утренний пуш в интерфейсе Decision Room, корпоративном мессенджере (Telegram/Slack/Teams) или по электронной почте.
